# هَدْي — منظّم اليوم على السنة (تطبيق PWA بـ Flutter)

منظّم لليوم على هدي السنة: الصلوات والرواتب والضحى والقيام والوتر والأذكار والورد والحفظ، مع العمل والأسرة والحاجات الشخصية والترتيب والتنظيف، في جدول واحد هادئ. لكل مهمة تتبّع «نعم/لا» يومي.

## التشغيل والبناء

يلزم Flutter (القناة stable) فقط.

```bash
cd sunnah_day
flutter pub get
flutter run -d chrome                 # للتجربة
flutter build web --release           # للنشر → المخرجات في build/web
```

> ملاحظة: المشروع لا يحتوي على مجلدات المنصات الأخرى (android/ios…). إن أردتها لاحقاً نفّذ `flutter create . --platforms=web,android` داخل المجلد.

## النشر على GitHub Pages وCloudflare Pages (بنفس الملفات)

الإشعارات وتحديد الموقع وعامل الخدمة تحتاج **HTTPS**، وكلا الخدمتين توفره.
المشروع يضبط مساره تلقائياً (يعمل من الجذر أو من `github.io/اسم-المستودع/`)، فلا حاجة لتغيير `--base-href`.

### 1) ارفع الكود إلى GitHub
ارفع **مجلد المشروع كاملاً** (وليس `build/web`) إلى مستودع جديد على الفرع `main`، بما فيه المجلد المخفي `.github`.
عند كل رفع يبني سير العمل `.github/workflows/deploy.yml` التطبيق وينشره على فرع اسمه `gh-pages`.

> أول مرة: من تبويب Actions تأكد أن التشغيل نجح (علامة خضراء)، وأن الفرع `gh-pages` ظهر.
> إن فشل بسبب الصلاحيات: Settings ← Actions ← General ← Workflow permissions ← **Read and write permissions**.

### 2) GitHub Pages
Settings ← Pages ← Source: **Deploy from a branch** ← Branch: `gh-pages` / `(root)` ← Save.
يصبح الرابط: `https://اسمك.github.io/اسم-المستودع/`

### 3) Cloudflare Pages (من نفس المستودع)
Workers & Pages ← Create ← Pages ← Connect to Git ← اختر المستودع، ثم:
- Production branch: `gh-pages`
- Build command: *اتركه فارغاً*
- Build output directory: `/`

يصبح الرابط: `https://اسم-المشروع.pages.dev` ويتحدّث تلقائياً مع كل بناء جديد.

### بديل بدون GitHub Actions
نفّذ `flutter build web --release` محلياً ثم ارفع **محتوى** `build/web` (وليس المجلد نفسه) إلى مستودع أو فرع، واستخدمه بنفس الخطوتين 2 و3. لـ Cloudflare يمكنك أيضاً سحب مجلد `build/web` مباشرة (Direct Upload).

بعد الفتح على الجوال: «إضافة إلى الشاشة الرئيسية» لتثبيته كتطبيق.

## هيكل الكود

| الملف | وظيفته |
|---|---|
| `lib/models.dart` | النماذج: المهمة، مواقيت اليوم، الإعدادات |
| `lib/defaults.dart` | الجدول الافتراضي (قابل للتعديل كله من التطبيق) |
| `lib/app_state.dart` | الحالة، جلب المواقيت (Aladhan)، التتبع، جدولة التنبيهات |
| `lib/bridge.dart` + `web/notify.js` | الإشعارات، الأصوات، الموقع، رفع ملف صوتي |
| `lib/pages/` | شاشات: اليوم، المهام، المواقيت، الإعدادات |

## كيف تعمل المواقيت

- **الحساب داخل الجهاز:** تُحسب المواقيت فلكياً من إحداثياتك (`lib/solar.dart`)، فتعمل دون إنترنت وتتبع ساعة جهازك والوقت الصيفي/الشتوي تلقائياً. جُرّبت الخوارزمية مقابل Aladhan في مكة ولندن والبيضاء فتطابقت في الدقيقة (الفجر والشروق والظهر والمغرب والعشاء)، ويختلف العصر دقيقة واحدة أحياناً.
- **الموقع:** تلقائي (GPS بإذنك) أو يدوي: اكتب المدينة والدولة فتُحوَّل إلى إحداثيات عبر خدمة Open-Meteo.
- **الجهة المعتمدة:** تُختار تلقائياً حسب الدولة (`lib/methods.dart`)، أو اختر طريقة بنفسك أو أدخل زوايا مخصصة. ليبيا تستخدم الطريقة الافتراضية (رابطة العالم الإسلامي) بلا تخصيص لمدينة، وتضبط فروق الدقائق من الإعدادات.
- **التعديل الدقيق:** ±15 دقيقة لكل وقت لمطابقة مسجدك، وتصحيح التاريخ الهجري بالأيام.
- المهام مرتبطة بالمواقيت (مثلاً «ركعتا الضحى = الشروق + 25 دقيقة»، «القيام = بداية الثلث الأخير»)، فتتحرك وحدها مع تغيّر الفصول، ويمكنك تثبيت أي مهمة على وقت محدد.

## التنبيهات

أربعة أنواع، لكل منها تفعيل وصوت ومدة مستقلة: **قبل الأذان**، **الأذان**، **الإقامة** (دقائق مخصصة لكل صلاة)، **المهام**. الأصوات المدمجة مولّدة داخل المتصفح، ويمكنك اختيار «ملف صوتي خاص بي» لكل نوع (مثل صوت الأذان) ويُحفظ على جهازك.

### حدود يجب معرفتها
- التنبيهات تُطلق من التطبيق نفسه، فتعمل ما دام **مفتوحاً** (نافذة أو تطبيقاً مثبتاً، حتى في الخلفية). المتصفحات لا تتيح جدولة تنبيهات محلية والتطبيق مغلق تماماً؛ ذلك يحتاج خادم Web Push، وهو إضافة ممكنة لاحقاً.
- المتصفحات تمنع الصوت قبل أول لمسة للصفحة بعد فتحها.
- iOS: الإشعارات تعمل فقط بعد «إضافة إلى الشاشة الرئيسية» (iOS 16.4 فما فوق).
- تُعرض المواقيت بتوقيت جهازك؛ إن كانت منطقة جهازك الزمنية تخالف مدينتك فستنزاح الأوقات.

## الخصوصية
كل بياناتك (المهام والإنجاز والإعدادات) تُحفظ في متصفحك فقط. الطلبات الخارجية الاختيارية: `api.bigdatacloud.net` (اسم المدينة والدولة من الإحداثيات) و`geocoding-api.open-meteo.com` (تحويل اسم المدينة إلى إحداثيات) و`api.aladhan.com` (التاريخ الهجري فقط، وله بديل حسابي دون إنترنت) و`fonts.gstatic.com` (خط تجوال). المواقيت نفسها لا تحتاج أي طلب.


## التنبيهات في الخلفية (مهم)

المتصفح يجمّد التطبيق المغلق، لذلك لا تصل التنبيهات في وقتها بدون خادم دفع.
أُضيف مجلد `push-worker/` (Cloudflare Worker مجاني) يرسل Web Push في الموعد.
اتبع `push-worker/README.md` مرة واحدة، ثم ضع رابط الخادم في `web/config.js`.

- بدون الخادم: التنبيهات تعمل فقط والتطبيق مفتوح.
- معه: تصل والتطبيق مغلق، بصوت الإشعارات الافتراضي للجهاز.
- آيفون: ثبّت التطبيق على الشاشة الرئيسية أولاً. أندرويد: استثنه من توفير البطارية.
- إن كنت مثبّتاً نسخة قديمة قد تحتاج إعادة فتحها مرتين ليحلّ عامل الخدمة الجديد (`hady_sw.js`).


## نسخة أندرويد (تنبيهات مضمونة في الخلفية)

على أندرويد تُجدول التنبيهات في منبّه النظام الدقيق (AlarmManager)، فتصل في وقتها والتطبيق مغلق وبعد إعادة تشغيل الهاتف، ولا تحتاج خادم push.
الكود نفسه؛ الاختلاف في `lib/bridge_native.dart` (أندرويد) مقابل `lib/bridge_web.dart` (ويب).

1. ارفع المشروع إلى GitHub.
2. من تبويب Actions شغّل **Build Android APK** (Run workflow).
3. حين ينتهي نزّل `hady-android-apk` من Artifacts وفكّ الضغط ثم ثبّت `app-release.apk` على الهاتف (اسمح بالتثبيت من مصدر غير معروف).
4. افتح التطبيق: الإعدادات ← «التنبيهات في الخلفية» ← **تفعيل**، وامنح إذن الإشعارات وإذن «المنبّهات والتذكيرات».
5. إن كان هاتفك شاومي/أوبو/هواوي: فعّل «التشغيل التلقائي» وأوقف توفير البطارية للتطبيق.

لا توجد نسخة ويندوز مجدولة: المنصة لا تتيح لتطبيق مغلق أن يُظهر تنبيهاً في وقته بهذه المكتبة، فلن تحلّ المشكلة.
كل تشغيل للسير يوقّع الـAPK بمفتاح مختلف، فعند التحديث احذف النسخة القديمة أولاً.
